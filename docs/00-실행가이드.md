# 로컬 실행 가이드

## 1. 백엔드

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload
```

- http://127.0.0.1:8000/docs — Swagger UI, http://127.0.0.1:8000/ — 지금 쓰는 저장소·AI
- 키가 없으면 메모리 저장소 + mock AI 로 돈다. 시작할 때 `data/seed_nvda_daily.csv`(NVDA 종가 502건)가
  자동으로 들어간다. 메모리 저장소라 서버를 끄면 추가한 데이터·대화는 사라진다.

## 2. 프론트엔드

```bash
cd frontend
python3 -m http.server 5500
```

http://127.0.0.1:5500 — `config.js` 가 로컬 백엔드(127.0.0.1:8000)를 가리킨다. 백엔드는 이 두 주소
(`localhost:5500`·`127.0.0.1:5500`)만 CORS 허용한다 — 다른 포트로 띄우면 `CORS_ORIGINS` 에 넣는다.

## 3. 테스트

```bash
cd backend
pip install -r requirements-dev.txt
pytest -q
```

키 없이 돈다(셸에 키가 있어도 쓰지 않는다). 데이터 CRUD·요약 계산·채팅 컨텍스트 주입·AI 실패 처리·
대화 기록·입력 검증·CORS 를 본다. GitHub 에 push 하면 Actions 가 같은 테스트를 돌린다.

## 4. 실제 OpenAI·Firestore 로

```bash
cd backend
cp .env.example .env     # .env 는 .gitignore — 커밋되지 않는다
# OPENAI_API_KEY, FIREBASE_CREDENTIALS_JSON(키 파일 내용 한 줄), FIREBASE_PROJECT_ID 채우기
uvicorn main:app --reload
```

http://127.0.0.1:8000/ 의 `storage`·`ai_provider` 가 `firestore`·`openai` 로 바뀌면 적용된 것이다.
키가 잘못됐으면 서버가 뜨지 않고 원인을 한 줄로 알려 준다.
