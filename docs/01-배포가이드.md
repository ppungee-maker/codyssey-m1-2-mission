# M1-2 배포 가이드 (Firebase + Render + Vercel)

순서가 중요하다: **Firebase 키 → Render(백엔드) → Vercel(프론트) → Render 의 CORS 에 Vercel 주소**.
프론트는 백엔드 주소가, 백엔드 CORS 는 프론트 주소가 필요해서 마지막에 한 번 되돌아간다.

## 0. 준비물

- [ ] GitHub 저장소(이 저장소)
- [ ] Firebase 프로젝트 + 서비스 계정 키(JSON 파일)
- [ ] OpenAI API 키 (사용량 한도를 낮게 걸어 두기 권장)
- [ ] Render 계정(무료), Vercel 계정(무료) — 둘 다 GitHub 로 가입하면 저장소 연결이 쉽다

## 1. Firebase — Firestore 와 서비스 계정 키

1. [Firebase 콘솔](https://console.firebase.google.com) → 프로젝트 추가.
2. Firestore Database → 데이터베이스 만들기 → **프로덕션 모드**, 위치 `asia-northeast3`(서울).
   프로덕션 모드는 브라우저에서 직접 읽기·쓰기를 전부 막는다. 이 서비스는 백엔드가 관리자 키로만
   접근하므로 규칙을 열 필요가 없다.
3. 프로젝트 설정(톱니) → 서비스 계정 → **새 비공개 키 생성** → JSON 파일 저장.
   이 파일은 커밋하지 않는다. 내용을 한 줄로 만들어 둔다(4단계에서 붙여 넣음):
   ```bash
   python -c "import json;print(json.dumps(json.load(open('key.json'))))"
   ```
4. 프로젝트 설정 → 일반 → **프로젝트 ID** 를 적어 둔다.

컬렉션(`data`, `conversations`)은 첫 요청 때 자동으로 생긴다. 서버가 처음 뜰 때 `data` 가 비어
있으면 시드 CSV(NVDA 502건)가 한 번 들어간다(`SEED_ON_STARTUP=false` 로 끌 수 있다).

## 2. Render — 백엔드

1. Render 대시보드 → **New → Blueprint** → 이 저장소 선택. 루트의 `render.yaml` 이 설정을 채운다
   (Root Directory `backend`, 시작 명령 `uvicorn main:app --host 0.0.0.0 --port $PORT`).
   서비스 이름은 `render.yaml` 의 `m12-ai-assistant-api` 그대로 둔다 — 주소가
   `https://m12-ai-assistant-api.onrender.com` 이 되어 README 「배포 URL」과 맞는다.
2. 물어보는 값을 넣는다:

   | 키 | 값 |
   |---|---|
   | `OPENAI_API_KEY` | OpenAI 키 |
   | `FIREBASE_CREDENTIALS_JSON` | 1-3 의 **한 줄 JSON 내용**(파일 경로 아님) |
   | `FIREBASE_PROJECT_ID` | 1-4 의 프로젝트 ID |
   | `CORS_ORIGINS` | 일단 비워 둔다 — 4단계에서 채운다 |

3. 배포가 끝나면 확인:
   - `https://<서비스>.onrender.com/` → `"storage": "firestore"`, `"ai_provider": "openai"`
     (memory·mock 이 보이면 키가 안 들어간 것)
   - `https://<서비스>.onrender.com/docs` → Swagger UI
4. 키를 잘못 넣으면 서버가 **뜨지 않는다**(메모리·mock 으로 몰래 바꾸지 않음). Render → Logs 에
   원인이 한 줄로 나온다 — 예: 「FIREBASE_CREDENTIALS_JSON 이 JSON 이 아닙니다」.

**콜드스타트**: 무료 인스턴스는 15분 동안 요청이 없으면 잠들고, 다음 첫 요청은 30초~1분 걸린다.
프론트가 「서버를 깨우는 중」 안내를 띄우고 자동으로 다시 시도한다. 시연 직전에 한 번 열어 두면 깨어 있다.

## 3. Vercel — 프론트엔드

1. [vercel.com/new](https://vercel.com/new) → 이 저장소 Import.
2. **Root Directory = `frontend`**. Framework Preset = Other. 빌드 명령·출력 폴더는 `frontend/vercel.json` 이 정한다.
   Project Name 은 기본값 `codyssey-m1-2-mission` 그대로 — 주소가 `https://codyssey-m1-2-mission.vercel.app` 이
   되어 README 와 맞는다. 이름이 이미 쓰이고 있어 다른 주소가 나오면 README 표를 그 주소로 고친다.
3. Environment Variables 에 `API_BASE_URL` = 2단계 Render 주소(예: `https://m12-ai-assistant-api.onrender.com`).
   빌드 때 `scripts/write-config.js` 가 이 값으로 `config.js` 를 만든다. 값이 없으면 빌드가 실패한다.
4. Deploy → 나온 주소(예: `https://m12-ai-assistant.vercel.app`)를 적어 둔다.

## 4. CORS 마무리 — Render 에 Vercel 주소

Render → 서비스 → Environment → `CORS_ORIGINS` = 3-4 의 Vercel 주소(여러 개면 콤마) → 저장하면 재배포된다.
안 하면 브라우저 콘솔에 CORS 오류가 나고 화면에 「서버에 연결하지 못했습니다」가 뜬다.

## 5. 최종 점검 (채점 1번 항목 순서)

- [ ] Vercel 주소 접속 → 요약 막대·그래프가 뜬다
- [ ] `<Render 주소>/docs` → Swagger UI
- [ ] 화면에서 데이터 추가 → 목록·요약 건수가 바뀐다 → Firebase 콘솔 `data` 컬렉션에 문서가 생겼다
- [ ] 「요즘 추세가 어때?」 → 요약 수치를 근거로 한 GPT 답변(응답의 `provider` = `openai`)
- [ ] 대화 목록에서 이전 대화를 눌러 불러오고 이어서 질문
- [ ] 휴대폰으로 같은 주소 → 채팅·데이터 추가가 된다
- [ ] 실제 주소가 README 「배포 URL」 표와 같은지 확인한다(다르면 표를 고친다)
